# KrishiSetu Voice Agent Integration

## Current implementation

The FastAPI backend serves the Twilio voice integration on the existing API
process at port `8000`; it does not start a separate AI/RAG server. The
`/farmer/ivr` page distinguishes this live phone flow from its browser-only
keypad simulator, and `/officer/voice-escalations` exposes callback requests to
authorized officers.

The call flow supports Hindi and English, DTMF and speech input, and policy
answers only when the RAG response contains a `VERIFIED` citation. Account
details require a short-lived SMS one-time code sent to the registered mobile.
Grievance and callback requests are saved only after explicit keypad
confirmation. Raw speech transcripts and recordings are not retained; call
metadata and callback-request summaries are stored in the local SQLite
database.

## Configuration

Set these variables in the backend environment. `.env.example` contains names
only; never commit actual credentials.

```dotenv
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_PHONE_NUMBER=
TWILIO_WEBHOOK_PUBLIC_URL=
VOICE_OTP_SECRET=
VOICE_PRIVATE_DATA_ENABLED=false
VOICE_SESSION_TTL_SECONDS=1800
VOICE_LOG_RETENTION_DAYS=30
```

`TWILIO_WEBHOOK_PUBLIC_URL` must be the public origin only, for example
`https://voice.example.org` (no path, query, or fragment). If it is unset, the
backend uses `PUBLIC_BASE_URL` as a compatibility fallback; the Twilio-specific
setting takes precedence when both are set. Production requires HTTPS.
Configure a Twilio phone number's incoming voice webhook as
`POST https://<public-origin>/api/v1/voice/incoming` and its call status
callback as `POST https://<public-origin>/api/v1/voice/status`. Subsequent
`<Gather>` action URLs are generated by the backend.

For an existing TwiML App configured with `POST https://<public-origin>/ivr`,
the backend also accepts `/ivr` as a compatibility alias for the signed
incoming-call webhook. The canonical endpoint remains
`/api/v1/voice/incoming`; do not use `/ivr` for status callbacks.

For private-data SMS verification, configure a Twilio account SID, auth token,
SMS-capable sender number, and an independent high-entropy `VOICE_OTP_SECRET`.
Keep `VOICE_PRIVATE_DATA_ENABLED=false` unless the deployment has an approved
private-data adapter; production currently keeps private actions disabled.
Caller ID alone is never treated as identity verification.

From `backend/`, run:

```text
uv sync
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

The frontend runs separately on port `3000`. `GET /api/v1/voice/status`
reports the configured feature flags; it is not a live connectivity check
against Twilio.

## HTTP endpoints

All paths below are under `/api/v1/voice`.

| Method | Path | Access / purpose |
|---|---|---|
| GET | `/status` | Public readiness flags and configured phone number |
| POST | `/incoming` | Signed Twilio incoming-call webhook |
| POST | `/language` | Signed language-selection action |
| POST | `/menu` | Signed main-menu action |
| POST | `/gather` | Signed keypad/speech gather action |
| POST | `/process` | Signed policy question or menu action |
| POST | `/verify` | Signed OTP-verification action |
| POST | `/continue` | Signed confirmation / next-action callback |
| POST | `/status` | Signed Twilio call-status callback |
| POST | `/recording` | Signed recording-status callback; recording is not stored |
| POST | `/hangup` | Signed call-end callback |
| GET | `/calls` | Authenticated call history; farmers see only their verified calls |
| GET | `/my-escalations` | Farmer's own voice escalation requests |
| GET | `/officer/escalations` | Officer/admin escalation queue |
| POST | `/officer/escalations/{id}/status` | Officer/admin follow-up status update |

`POST /ivr` is a root-level compatibility alias for `POST /incoming`.
Twilio webhook requests must be form-encoded and pass Twilio signature
validation against the configured public origin. Webhook bodies and field
counts are capped. Private call-history and escalation routes use the
application session and role checks.

## Security and retention

- OTPs expire after five minutes, allow at most three verification attempts,
  and are stored as HMAC digests rather than plaintext.
- OTP sending is limited to two messages per user in a ten-minute window.
- A call is limited to eight policy queries.
- Private-data and request actions require verified identity; grievance and
  callback writes additionally require keypad confirmation.
- Ended-call metadata and unanswered-query digests older than the configured
  retention (default 30 days) are removed by startup cleanup. Non-ended call
  sessions are not pruned by that cleanup. Pending request summaries are
  cleared at call end or after their short processing window.
- Confirmed callback escalation summaries remain in the officer queue; an
  automatic retention/deletion policy for those records has not yet been
  defined. The 30-day call-history cleanup does not delete escalation records.
- The current SQLite/demo adapter is not a production data-store substitute.
  Production use requires an approved persistent data/auth adapter, reviewed
  source documents, secrets management, and operational controls.

## Cost and operational considerations

There are no fixed cost estimates here. Budget for the provider's phone-number
rental, inbound call minutes, SMS delivery, and any speech/AI usage enabled by
the account; rates depend on country, destination, and account configuration.
Check the current provider pricing and usage limits before enabling a public
number. No live call, SMS delivery, production webhook, or cost was exercised
as part of this implementation.

## Known limitations

- The local policy chunks are currently marked `EXTRACTED`, not `VERIFIED`, so
  the call flow correctly abstains from speaking policy answers until an
  authorized review verifies sources.
- Chhattisgarhi speech is not available on the phone line.
- The speech-confidence threshold is provisional and has not been calibrated
  with real calls.
- The officer queue is backed by the local demo SQLite store; it is not wired
  to Supabase or a production case-management system.
- Escalation-summary retention needs a product/operator decision before
  production use.
- The readiness endpoint checks configuration presence, not successful
  provider authentication, number capability, SMS delivery, or webhook
  reachability.
